# Агенты для рабочих процессов компании

Читают учёт, документы и сообщения с объекта. Считает программа. Спорный шаг остаётся у человека. В боевую базу из чата ничего не проводится.

Вопрос к живой 1С обычными словами — отдельная страница: **[1C Sheriff](https://github.com/MattKup/1c-sheriff)**. Сайт и заявка: [officeclan.ru](https://www.officeclan.ru).

## Документы, которые можно проверить

Пачку договоров, сканов и таблиц можно отдать подряд. Каждый файл сразу получает место в очереди и не теряется, если обработчик перезапустился. Тот же файл с теми же настройками второй раз не считается.

Дальше у каждой страницы свой путь. Пустой лист пропускается. Цифровой PDF, Word, Excel и CSV читаются сами, без модели. Скан идёт в основное распознавание. Сложная вёрстка, где сетка и картинка спорят с текстом, уходит более сильной модели, и доля таких дорогих страниц ограничена, чтобы один кривой документ не съел весь бюджет.

Криво лежащий лист сначала выравнивается. Уверенный поворот на бок делается сам. Сомнительное направление не крутят наугад, а отдают человеку. Малый доворот поправляет лист, который положили чуть наискось. Слабый наклон не трогают, чтобы не испортить ровную страницу. После распознавания координаты ячейки возвращаются на исходный лист, и превью совпадает с тем, что видит глаз.

Если первый проход не принят, страница читается второй моделью целиком. Если и этого мало, лист режется на полосы и плитки, не больше четырёх кусков. Побеждает лучший кандидат. Два сырых текста в одну кашу не склеиваются. В факты попадает только принятое. Пустое, задвоенное и зацикленное остаётся пометкой на проверку. На спорный прямоугольник можно вызвать обе модели рядом. Обе версии остаются непроверенными, пока человек не выберет.

## Утренний радар по 1С

Руководитель получает в Telegram утреннюю сводку по УНФ ещё до планёрки. Где просели деньги, где остаток ушёл за порог, где сигнал уже стоит внимания. Цифру считает база. Модель только произносит уже посчитанное. Данные забираются из 1С учёткой на чтение. Под другую компанию меняется профиль порогов, а не просьба к чату. Для встречи есть показ на вымышленной фирме.

## Сверка реестров с 1С:УНФ

Реестр поставщика или покупателя ложится рядом с заказами УНФ. Точный ключ сходится сам. Дырявая строка допускается к оценке похожести только когда ключа нет. Суммы сверки живут в своей базе. В учёт уходит черновик. Кнопку проведения нажимает человек, который видит сошедшиеся строки и спорные. Скан может прочитать модель. Вердикт «это один заказ» выносит правило.

## Тендер и бланк

Разобранные страницы превращаются в решение по закупке. Условие встаёт на свою полку: к участнику, к товару, обязанность поставщика, обязанность заказчика, оплата. Рядом риски, дыры и черновик предложения. Балл показывает состав и не назначает участие. Человек ставит GO, REVIEW или NO-GO и оставляет причину. Бланк заполняется подтверждёнными значениями, у каждого поля есть источник. Подпись и отправка остаются у человека.

## С объекта в задачу

Прораб кидает фразу, голос или фото. Черновик ещё не факт. ПТО утверждает объект, объём и адресата. Пустое поле догадкой не заполняется. Дальше одна задача одному человеку. Срочное ждёт час, обычное — рабочий день. Одно напоминание в середине срока, потом эскалация. Ответ гасит таймер. Повтор того же сообщения вторую задачу не рождает. В работу уходит ссылка на исходник. Показ собран на вымышленном объекте.

## Голос ремонта

Одна фраза с объекта становится черновиком на доске: задача, покупка, блокер или вопрос по комнате. В работу пункт попадает после одного подтверждения. Заказчик видит весь объект, мастер — только своё. Закрытие приходит с фото. Объект можно вести одному, без бригады.

## Срез производства

Номер счёта — и видно состояние заказа: наряд, приёмка, отгрузка, срок по нормам. Ответ собирается из таблиц, которые цех уже ведёт. Ввод в цехе не переучивается. Имена в облачный чат не уходят.

## Платформа на команду

Свой сервер, свои модели. Общий рабочий чат для агентов, поиск юриста по своим документам, сверка реестров для бухгалтерии по расписанию. На пилоте это внутренний чат компании.

## Радар рынка

Открытые ленты собираются в темы: закупки, вакансии, GitHub, Product Hunt, отзывы приложений. Тема получает оценку, где спрос обогнал предложение. «Почему сейчас» собирается только из посчитанных факторов. Модель пересказывает готовый отчёт. Веса потом двигаются по фактическим исходам.
