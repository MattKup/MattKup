# Агенты для рабочих процессов компании

Это карта продуктов для операционной работы. Их держит одно правило: программа читает то, что компания уже ведёт, считает сама, а человек подтверждает шаг, который меняет деньги, документ или учёт.

Код и данные заказчиков закрыты. Ниже у каждого контура три слоя: зачем он бизнесу, на каком принципе держится и какая техника за ним стоит. Техника есть только там, где контур уже собран в коде.

Вопрос к живой базе 1С вынесен на отдельную страницу: **[1C Sheriff](https://github.com/MattKup/1c-sheriff)**. Заявка на подключение: [officeclan.ru](https://www.officeclan.ru).

## 1C Sheriff — вопрос к 1С обычными словами

Руководитель, бухгалтер и отдел продаж спрашивают базу так, как спрашивают коллегу. Долг, остаток, продажа или заказ приходят суммой из регистра. Названия в чате скрыты, полный список с настоящими именами открывается на своём компьютере.

**Принцип**

- База открыта только на чтение. Расширение в 1С не ставится.
- Имена, реквизиты и даты рождения заменяются до отправки в чат. Настоящие значения открываются локально.
- Суммы и остатки приходят из регистров 1С.
- Если строк пришло не все, это сказано прямо.

**Техника.** Локальный шлюз между чатом (Claude, Cursor, Codex) и опубликованными данными 1С. После подключения конфигурация определяется по метаданным. Внутри 36 запросов: Управление торговлей — 11, Бухгалтерия — 10, ЗУП — 9, УНФ — 6.

## Документы, которые можно проверить

Договор, скан или таблица становятся текстом, с которым можно сверить оригинал. Пустая, кривая или спорная страница в уверенный факт не превращается. Этот сервис читает документ. Решение по закупке, сверка и бланк живут отдельно и забирают у него уже разобранные страницы.

**Принцип**

- Цифровой PDF, Word, Excel и CSV читаются без модели. Скан идёт в распознавание. Сложная вёрстка уходит более сильной модели, и доля таких страниц ограничена.
- Уверенный поворот на бок делается сам. Сомнительное направление отдаётся человеку. Слабый наклон не трогается.
- В факты попадает только принятая страница. Два сырых текста в одну кашу не склеиваются. Спорный участок можно прочитать двумя моделями рядом, обе версии ждут выбора человека.

**Техника.** Отдельный сервис. Файл принимается в очередь до начала обработки, поэтому перезапуск его не теряет. Тот же файл с теми же настройками второй раз не считается. На выходе страницы, таблицы и фрагменты с привязкой к исходному листу.

## Утренний радар по 1С

Директор до планёрки получает в Telegram сводку по УНФ: где просели деньги, где остаток ушёл за порог, какой сигнал уже требует внимания. Для встречи есть показ на вымышленной фирме.

**Принцип**

- Цифру считает база. Модель формулирует уже готовый сигнал.
- Данные забираются из 1С учёткой на чтение.
- Другая компания получает другой профиль порогов и полей.

**Техника.** УНФ по стандартному каналу чтения → PostgreSQL → сигналы по порогам → текст в Telegram. Контур локальный.

## Сверка реестров отгрузки

Бухгалтер кладёт реестр поставщика рядом с заказами. Сошедшиеся строки уже заполнены. Спорные лежат отдельным списком, а не чужим заказом.

**Принцип**

- Сопоставление идёт каскадом: сначала номер сделки, потом договор и приложение, потом более слабые признаки. Строка без ключа догадкой в заказ не ставится.
- В сошедшуюся строку пишутся дата получения и фактическое количество. Остальные поля не трогаются.
- Что не сошлось, остаётся кандидатом на разбор человеком.

**Техника.** Реестр читается сервисом документов, дальше срабатывает фиксированный каскад. На выходе заполненный лист и список спорных строк. Проведение в 1С этим шагом не выполняется.

## Закупка и бланк

Закупщик видит условия по полкам: к участнику, к товару, обязанность поставщика, обязанность заказчика, оплата. Рядом риски и черновик предложения. Идти в закупку или нет фиксирует человек.

**Принцип**

- Решение бывает трёх видов: участвовать, отложить на проверку, отказаться. Без причины оно не сохраняется.
- Балл показывает состав и покрытие. Участие он не назначает.
- Бланк собирается из полей, у которых есть источник. Подписывает и отправляет человек.

**Техника.** Разбор страниц делает сервис документов. Решение человека с причиной сохраняется отдельно от черновика, который подготовила модель.

## С объекта в задачу

Прораб присылает фразу, голос или фото. ПТО проверяет объект, объём и адресата. Дальше у одного человека одна задача и видимый срок. Показ собран на вымышленном объекте.

**Принцип**

- Черновик фактом не считается. Пустое поле догадкой не заполняется.
- Задача рождается только из адресного сообщения и назначается одному человеку на этом объекте.
- Срочное ждёт час, обычное — один рабочий день. Напоминание одно, в середине срока, затем эскалация. Ответ останавливает таймер.
- Повтор той же загрузки вторую задачу не создаёт. У факта остаётся ссылка на исходник.

**Техника.** Цикл собран в коде: роли, подтверждение, срок в часовом поясе объекта, защита от повтора. Пока задача не подтверждена, наружу она не уходит.

## Голос ремонта

Фраза с объекта становится черновиком на доске: задача, покупка, блокер или вопрос по комнате. На доске для других пункт появляется после одного подтверждения. Заказчик видит весь объект, мастер — только своё. Объект можно вести одному, без бригады. Закрытие приходит с фото.

**Принцип**

- Голос сначала черновик. В работу он попадает после подтверждения автором.
- У записи остаётся отрезок исходной фразы.
- Предметный словарь отделён от распознавания: одно и то же слово в разных работах не схлопывается в одну карточку.

**Техника.** Цепочка: запись → распознавание → черновик → подтверждение. Распознавание подключается отдельно, локально или внешним сервисом. В работу в обоих случаях идёт подтверждённый черновик.

## Свой сервер на команду

Компания держит модели у себя. Сотрудники работают через общий рабочий чат. Юрист ищет по своим документам. Бухгалтерия по расписанию получает сверку реестров. На пилоте это внутренний чат компании.

**Принцип**

- Модели и документы лежат на машине компании.
- Канал команды — общий рабочий чат.
- Сверка для бухгалтерии идёт отдельным заданием по расписанию.

**Техника.** Локальный запуск моделей, единая точка вызова, маршрутизация задач. Поиск юриста и сверка бухгалтерии — отдельные задания на этом же сервере.

## Радар рынка

Раз в прогон видно, где спрос обогнал предложение. Источники открытые: закупки, вакансии, GitHub, Product Hunt, отзывы приложений и соседние публичные ленты. Тема получает оценку. Фраза «почему сейчас» собирается из посчитанных факторов.

**Принцип**

- Оценка строится из измерений.
- Модель пересказывает готовый отчёт и формулирует боль, конкурентов и следующий шаг. Факторы спроса она не измеряет.
- История оценок хранится. Веса можно сдвинуть по фактическим исходам.

**Техника.** 16 открытых сборщиков, склейка сигналов в темы, оценка по измеренным факторам. Если модель не подключена, отчёт всё равно собирается.
